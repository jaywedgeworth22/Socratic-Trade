## Decisions & Trade-offs

- **No source changes.**  16.3.5 is a backport-only patch release.  Its contents
  (next/image disk-LRU 0-byte entry skip + empty-image reject, whole-app server NFTs under
  `output: 'standalone'` with an adapter, CSP nonce on loading/template script tags, `use cache`
  prerender signal retention) are all internal fixes.  There is no API, config, or codemod
  migration, so nothing in `src/**` or `app/**` needed to change.
- **`PLAN.md` intentionally not updated.**  The handoff protocol calls for `PLAN.md` to reflect
  scope/timeline/approach changes; a patch-level dependency bump changes none of those.
- **No codex-autofix round cap reached.**  This is round 1 (the branch carries 9 `[codex-autofix]`
  commits in its *history*, all from previously-merged main work — none authored on this PR).
- **Do not amend or force-push the dependabot commit.**  The doc updates ride as a separate commit
  on the PR branch so dependabot's own commit stays intact and `@dependabot rebase` keeps working.

**The 13 local `npm test` failures are environmental, not caused by this change.**  All 13 are
LLM-credential fail-closed assertions (`test/llm-provider.test.ts`, `test/chat-llm.test.ts`,
`test/framework-review.test.ts`, `test/openrouter-credits.test.ts`) that expect "user has no key"
to resolve to *no* credential.  `src/lib/db-api-keys.ts` has a test-mode operator fallback
(`NODE_ENV === "test"` + no user key -> borrow the ambient provider env var, with `openrouter`
falling back through `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, ...).  This agent sandbox exports
`ANTHROPIC_API_KEY`, so the fallback fires and the assertions see a key.  Re-running just those
four files with the LLM env vars unset gives **4 files / 60 tests passed, 0 failed** — which
isolates the cause to the sandbox environment.  GitHub-hosted `verify` CI sets no such key, so
the gate is unaffected.  Proof that the diff is not implicated: the PR touches only
`package.json` + `package-lock.json`, and none of the four files is in the diff.

Two stray working-tree artifacts produced by the local run were reverted before commit and are
**not** part of this change:

- `package-lock.json` — `npm install` churn (90 `libc` metadata lines removed by this npm's
  lockfile normalization).
- `ios/SocraticTradeTests/Fixtures/policy-contract.json` — `test/policy-ios-contract-fixture.test.ts`
  *regenerates* the checked-in fixture as a side effect of running the suite.  It rewrote
  `learningReviewModel` from `claude-fable-5` to `claude-fable-latest`, matching
  `src/lib/defaults.ts:91`.  That drift is **pre-existing on `origin/main`** (its committed fixture
  says `claude-fable-5` while its source default is `claude-fable-latest`) and is out of scope for
  a dependency bump, so the fixture was restored rather than refreshed here.

The authoritative gate is the PR's required `verify` CI check, which re-runs
`tsc --noEmit` -> `npm test` -> `npm run build` on the pushed commit.
